群典是一个面向 QQ 群聊的 AstrBot 插件。引用一条消息就能把它收录下来，之后随时随机翻出来，或者一次爆出某位群友的全部“黑历史”。

## 功能一览

| 功能 | 说明 |
| ---- | ---- |
| **消息收录** | 文字、图片、QQ 表情、商城表情、回复关系和合并转发都能保存 |
| **随机群典** | 全群或指定成员随机发送，可按关键词搜索，尽量避开最近发过的 |
| **爆典合集** | 按时间查看某位成员参与的全部群典，支持分页和嵌套转发 |
| **图片卡片** | 把纯文字或图片记录渲染成纸面或墨色的引用卡片 |
| **统计排行** | 群内参与排行、收录排行和个人统计 |
| **戳一戳** | 戳机器人随机获取一条群典（默认关闭） |
| **定时任务** | 每日一典、那年今日和自动备份（默认关闭） |
| **投票收录** | 消息收到足够多的表情回应后自动收录（默认关闭） |
| **管理页** | 在 AstrBot 后台查看、删除、备份和检查数据 |

## 快速开始

### 安装

在 AstrBot Dashboard 的插件市场搜索“群典”并安装，然后重启或重载插件。

运行要求：

- AstrBot `>=4.29.0,<5`
- OneBot 11 / QQ，使用 `aiocqhttp` 适配器
- Python 依赖：`aiohttp>=3.9,<4`、`Pillow>=11.2.1,<13`

<details>
<summary>手动安装</summary>

进入 AstrBot 的插件目录并克隆仓库，目录名应保持为 `astrbot_plugin_iconic_quotes`：

```bash
cd AstrBot/data/plugins
git clone https://github.com/conFess233/astrbot_plugin_iconic_quotes.git
cd astrbot_plugin_iconic_quotes
```

使用 AstrBot 所在的 Python 环境安装依赖，然后重启 AstrBot：

```bash
python -m pip install -r requirements.txt
```

</details>

### 三步上手

**1. 收录：** 引用想要收录的消息，发送：

```text
/添加群典
```

**2. 翻看：** 随机看一条，或者搜索：

```text
/群典
/群典 最后一把
```

**3. 爆典：** 查看某位成员的记录：

```text
/群典 @某人
/爆典 @某人
```

## 指令

示例使用默认唤醒前缀 `/`；改过前缀时，换成你配置的前缀即可。

| 指令 | 作用 |
| ---- | ---- |
| `/添加群典` | 收录引用的消息或合并转发 |
| `/群典` | 随机发送当前群的群典 |
| `/群典 <关键词>` | 随机发送全群包含关键词的群典 |
| `/群典 #记录ID` | 发送指定记录，ID 至少 4 位 |
| `/群典 @某人` | 随机发送指定成员的群典 |
| `/群典 @某人 <关键词>` | 随机发送该成员本人说过、包含关键词的群典 |
| `/爆典 @某人 [页码]` | 按时间查看该成员参与的全部群典 |
| `/群典 info` | 查看当前群的汇总统计 |
| `/群典 info @某人` | 查看指定成员的个人统计 |
| `/群典 排行` | 查看参与排行和收录排行 |
| `/群典 help` | 查看帮助，也可以用 `/群典 帮助` |
| `/删除群典 <文字或 #记录ID>` | 预览待删除的记录，并开启 60 秒确认窗口 |
| `/确认删除` | 删除自己最近一次预览的记录 |

**不加前缀也能用：** 除了两个删除指令，上面的指令都可以去掉前缀直接发送，比如 `群典`、`群典 @某人`、`爆典 @某人`。这些关键词可以在配置里修改或关闭，关闭后带前缀的指令仍然可用。

<details>
<summary>关键词的触发规则</summary>

- 正文必须以关键词开头，并完整匹配语法：`群典真好玩` 不会触发，`群典 真好玩` 会搜索“真好玩”。
- 消息开头可以先引用消息或 `@Bot`。
- 关键词前最多放一个成员 @：`@甲 群典` 和 `群典 @甲` 都能查询甲的记录。
- `@甲 @乙 群典 消息` 会被当作普通聊天，不回复也不拦截。
- `群典 @甲 @乙` 会提示只能指定一名成员，`群典 @甲 @甲` 按同一名成员处理。
- 关键词冲突时爆典语法优先。
- 调用格式错误时，插件会在失败原因后附上当前操作的用法，用法内容可以配置。

</details>

## 功能说明

### 收录

- **普通消息：** 保存发送者 QQ、昵称快照、正文、来源时间和收录信息。
- **合并转发：** 整体计为一条记录，递归保留节点顺序、作者、内容和子转发 ID。
- **回复关系：** 被收录的消息如果回复了别人，被回复的消息会保存为本地快照；添加指令本身用来选择来源的引用不会被存进去。
- **表情：** QQ 表情保存 ID 并原生重放；商城表情同时保存本地图片，原生发送失败时降级为图片；Unicode Emoji 按普通文字保存。
- **图片：** JPEG、PNG、WebP 和 GIF 按内容哈希存储。

语音、视频和文件不会保存。没有任何可保存内容时，会明确提示添加失败。达到记录、媒体或内容上限时，整次添加都会失败，不会截断内容，也不会悄悄淘汰旧记录。

### 查询

- **随机抽取：** 普通记录和合并转发同样对待，单次不重复。最近发过的记录排到最后，其余完全随机，可用 `anti_repeat_window` 调整。
- **全群搜索：** `/群典 <关键词>` 搜索全群记录的正文、回复快照和转发节点。
- **成员搜索：** `/群典 @某人 <关键词>` 只匹配该成员本人的正文、转发节点和回复快照，不区分大小写；不搜索其他人的内容、昵称、时间、文件名或图片里的文字。
- **记录 ID：** 收录成功时会告诉你 ID，管理页也能查看。`#记录ID` 没有对应记录时按普通文字搜索，匹配到多条时会提示提供更长的 ID。
- **删除：** `/删除群典` 命中多条时会列出它们的 ID，可以改用 `/删除群典 #记录ID` 只删其中一条。纯图片记录只能这样删除，或者在管理页删除。

### 爆典

`/爆典 @某人` 收集该成员作为作者或任一转发节点作者参与的记录，按收录时间从旧到新排列。多人的合并转发整体计为一条，不拆分也不重复计数。

记录数不超过每页条数时会直接发送全部内容；超过时先提示总页数，再用 `/爆典 @某人 页码` 获取指定页。

每条记录前默认有一个独立的“记录时间”节点，也可以改用实验性的原生时间（是否显示取决于 OneBot 实现），或者不显示。

### 发送方式

| 内容 | 发送方式 | 发送失败时 |
| ---- | -------- | ---------- |
| 单条文字 | `“金句内容”——发送者` | |
| 图片卡片 | 头像、正文、群昵称和记录时间 | 改为文字发送 |
| 多条记录 | 聚合为合并转发，节点使用原发送者的 QQ 和昵称 | |
| 原始合并转发 | 优先原样嵌入 | 展开为扁平合集，商城表情必要时降级为图片 |
| 回复关系 | 优先使用 QQ 原生回复 | 拆为被回复节点和回复节点 |

- 含 QQ 表情、商城表情或回复快照的记录不走卡片，直接按原消息发送，避免内容丢失。
- 爆典遇到缺失的媒体时保留其余内容，并用 `[图片资源缺失]` 或 `[表情资源缺失]` 占位。
- 超时或断线时消息可能已经送达，所以默认停止重试和降级，并提示你检查群聊。开启 `retry_on_ambiguous_failure` 后会按次数重试，但可能产生重复消息；最终仍未知时也不会换格式补发。

### 图片卡片

把 `send_mode` 设为 `card` 即可启用。超过 `card_max_height` 的内容会自动分页，不会被裁切。

卡片由文转图（t2i）服务渲染，默认使用 AstrBot“设置 → 外观 → 文本转图像”中的服务，未修改时是官方公共服务。如需更快，或者不想把内容发到外部，可以在本机部署 [astrbot-t2i-service](https://github.com/AstrBotDevs/astrbot-t2i-service)：

```bash
docker run -itd -p 8999:8999 soulter/astrbot-t2i-service:latest
```

然后把 `card_t2i_endpoint` 设为 `http://127.0.0.1:8999`。如果 AstrBot 也运行在 Docker 中，这里填该服务的容器名。

头像默认通过 API 临时获取，也可以用 `localize_avatars` 按 QQ 号缓存到本地；获取失败时使用内置的空白头像。

### 戳一戳

开启 `poke_enabled` 后，群成员戳机器人会随机收到当前群的群典。它沿用查询权限和黑白名单，冷却中不回复，只有戳机器人才有效。

选择图片模式时逐条生成卡片，失败时发送原消息；合并转发记录保持聊天记录的形式。

### 定时任务

- **每日一典：** 每天定时发送一条随机群典。
- **那年今日：** 发送往年同月同日收录的群典，当天没有时不发送。
- **自动备份：** 定期把完整备份写入 `backups/`，数据没有变化时跳过。文件名以 `auto-iconic-quotes-` 开头，可以在管理页导入。每份都包含全部图片，请按磁盘空间设置保留份数。

推送时间按服务器时区计算，只发给机器人收到过消息的群，并遵守群黑白名单。错过时间超过 30 分钟后当天不再补发。发送前会先记下当天已推送，所以发送失败或结果未知时不会重发。

### 表情回应投票

一条消息被足够多的成员贴上表情后会自动收录，并在群里提示结果。消息已收录或无法读取时只写日志，不打扰群聊。

- 同一人回应多个表情只算一票，机器人自己的回应不计票。
- 投票者需要有添加权限，并受黑白名单限制。
- 票数保存在内存中，重启后重新累计。
- 需要 OneBot 实现上报 `group_msg_emoji_like` 通知，比如 NapCat。

## 配置

全局配置可以在 AstrBot 的插件配置或“群典管理”页面修改。在管理页保存后立即生效，保存失败时保留草稿并继续使用旧配置；在宿主配置页保存后，AstrBot 会重载插件。

**群级覆盖：** 在管理页“配置 → 群聊覆盖”中可以按群号单独设置，未覆盖的字段继承全局值。支持覆盖的有关键词、发送方式、戳一戳、爆典、帮助、权限、用户名单、禁止收录名单、定时推送、表情投票和单群记录上限。

**作者别名：** 在管理页“配置 → 作者别名”中按“群号 → QQ → 别名”纠正旧合并转发节点和回复快照的作者，保存前会显示受影响的记录和作者数量。

## 管理页

插件详情页中的“群典管理”复用 AstrBot Dashboard 的端口和认证，无需单独部署。页面跟随 Dashboard 的明暗主题，窄屏和键盘都能操作。

| 页面 | 可以做什么 |
| ---- | ---------- |
| **记录** | 按群分页、搜索和筛选；查看正文、图片、回复快照和转发层级；单条或批量删除，或删除转发中的单个节点；预览卡片 |
| **配置** | 全局配置、群聊覆盖和高级 JSON 共用一份草稿，右侧列出全部改动；可用未保存的草稿预览帮助卡片和群典卡片 |
| **备份** | 导出 ZIP；按“上传 → 预检 → 确认影响 → 写入”合并导入，可选择同时恢复配置；运行完整性检查；清理头像缓存 |
| **审计** | 按群号、操作者和来源筛选全部删除记录 |

- 删除记录和清空头像缓存无法撤销，执行前会要求确认并写明数量。
- 刷新数据会放弃未保存的配置草稿，执行前同样会确认。
- 记录已导入但配置恢复失败时，会明确提示部分完成，原配置继续有效。

## 数据与安全

所有数据都保存在插件专属目录，且为**明文**，请保护好这个目录和导出的 ZIP 文件：

```text
AstrBot/data/plugin_data/astrbot_plugin_iconic_quotes/
├── quotes.sqlite3      # 记录、媒体引用、群级配置、头像索引与删除审计
├── media/              # 群典图片与商城表情，按 SHA-256 命名
├── avatars/<QQ号>.jpg  # 可选的头像缓存
└── backups/            # 导出的备份与导入时的临时文件
```

- **文转图隐私：** 使用卡片时，正文、昵称、头像和缩小后的图片会发送给文转图服务。默认是 AstrBot 配置的服务（未修改时为官方公共服务）；改用本地部署后，数据不会离开你的服务器。
- **写入安全：** 每次写入都在单个数据库事务中完成，失败不会留下半条记录。启动时会检查数据库完整性，未通过时插件停止初始化，不会用空库覆盖。
- **备份保留：** 手动导出的 ZIP 只保留最新 3 份，如需长期保存请下载或移出 `backups/`；自动备份按配置保留。
- **导入校验：** 导入备份时会校验路径、清单、文件哈希、图片格式和容量，预检通过并确认后才写入。
- **图片去重：** 同一张图片无论被多少个群收录都只保存一份，不再被任何记录引用时才会删除。
- **图片损坏：** 发送前只检查被抽中图片的存在和大小，内容被改写但大小不变时，要运行“完整性检查”才能发现。缺失或损坏的记录不参与随机群典。
- **头像缓存：** 启用后计入 `max_media_mb`。容量不足时优先清理无引用的头像，再按最久未使用清理，不会删除群典正文或图片。

<details>
<summary><b>从 1.x 升级</b></summary>

首次启动 2.0 时，插件会把旧的 `iconic_quotes/groups/*.json`、图片、头像缓存和删除审计迁入数据库，并把旧目录改名为 `iconic_quotes.migrated-<时间>` 保留，不删除任何旧文件。

- 无法读取的群文件会被跳过并在日志中列出，原文件仍在保留的旧目录中。确认迁移结果无误后，可以自行删除旧目录。
- 宿主配置中的群级覆盖和作者别名会自动迁入数据库。
- 1.x 导出的备份 ZIP 仍可在管理页导入。

</details>

## 已知限制

- 仅支持 OneBot 11 / QQ 群聊。
- 嵌套合并转发默认最多收录 3 层，可配置为 1～10 层，超限时整条添加失败。
- NapCat 会对 2～3 层存档递归重建原生转发；超过原生发送深度、非 NapCat 环境或明确发送失败时，会先提示再完整展开。
- OneBot 11 的转发节点不支持自定义头像，所以头像缓存只用于卡片和后台，不能替换合并转发气泡旁的头像。
- 插件优先读取节点的 `sender` 身份。查询旧记录时只在内存副本中按管理员别名、有效 QQ 和群内唯一完整昵称纠正，不会改写存档；无法确认的节点会显示一次提示。
